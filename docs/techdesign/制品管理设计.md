# 制品管理设计

## 1. 背景与目标

### 1.1 现状

平台触发流水线执行后，Argo Workflows 负责编译构建、镜像打包和推送。当前镜像推送（`push-image-nexus3`）已将镜像上传到 Nexus3，但存在两个问题：

1. **原始制品（如 Go 二进制、jar、前端 dist）没有上传到 Nexus3**，构建完就丢弃了。
2. **平台侧感知不到构建产出的制品和镜像**——上传到 Nexus3 之后，没有任何信息回传到后端，无法在平台上查看、追溯和管理制品。

### 1.2 目标

增加制品管理功能，实现：

- 制品信息（原始制品 + 镜像制品）在构建/推送后回传到后端，落地到 DB。
- 前端提供制品列表页，支持按应用、名称、分支、环境、类型筛选。
- 流水线执行详情页展示本次构建产出的制品信息。
- 新增原始制品上传 Nexus3 的统一任务模板（内含回传后端）。
- 改造镜像推送模板，在推送成功后回传镜像制品信息。

### 1.3 实施分期

| 阶段 | 内容 | 说明 |
|------|------|------|
| **第一步** | 制品表 + 后端 CRUD + 回传接口 + 前端制品列表页 + 流水线详情页制品展示 | 纯平台侧改造，不涉及 Argo YAML |
| **第二步** | 新增原始制品上传 Nexus3 模板 + 改造 push-image-nexus3 加回传 + 改造 go-cicd-pipeline 编排 + ConfigMap | 涉及 Argo YAML，需实际跑流水线验证 |

## 3. 数据库设计

### 3.1 制品表 DDL

文件：`sql/artifact.sql`

```sql
-- =============================================================================
-- 制品管理模块 DDL（artifact）
-- =============================================================================
-- 说明：
-- 1. 表为逻辑删除（deleted：0-未删除，1-已删除），由 MyBatis-Plus 全局配置接管。
-- 2. 记录流水线构建产出的制品信息，包括原始制品（Raw）和镜像制品（Image）。
-- 3. 每次流水线执行，原始制品和镜像制品各回传一条记录，通过 pipeline_run_id 关联。
-- =============================================================================

CREATE TABLE `artifact` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `app_name` varchar(200) NOT NULL COMMENT '应用名称，比如：go-web-demo',
  `name` varchar(255) NOT NULL COMMENT '制品名称，原始制品为二进制名，镜像制品为 repo 路径',
  `type` varchar(20) NOT NULL COMMENT '制品类型：RAW-原始制品，IMAGE-镜像制品',
  `git_branch` varchar(255) DEFAULT NULL COMMENT '构建时的 git 分支',
  `commit_id` varchar(64) DEFAULT NULL COMMENT '构建时的 commit id',
  `env` varchar(30) DEFAULT NULL COMMENT '环境标识（dev/test/prod）',
  `build_time` datetime DEFAULT NULL COMMENT '构建时间',
  `build_user` varchar(255) DEFAULT NULL COMMENT '构建人（触发流水线的用户）',
  `pipeline_run_id` bigint DEFAULT NULL COMMENT '流水线运行ID，对应 pipeline_run.id',
  `pipeline_run_name` varchar(200) DEFAULT NULL COMMENT '流水线运行名称，对应 pipeline_run.name（即 Argo Workflow name），用于跳转流水线详情',
  `artifact_repository` varchar(255) DEFAULT NULL COMMENT '制品仓库名，如 raw-go / go-web-demo',
  `artifact_repository_path` varchar(512) DEFAULT NULL COMMENT '仓库内相对路径',
  `artifact_url` varchar(1024) DEFAULT NULL COMMENT '制品完整地址，镜像可用于 docker pull，原始制品可用于下载',
  `size` bigint DEFAULT NULL COMMENT '制品大小（字节）',
  `sha256` varchar(65) DEFAULT NULL COMMENT '制品 sha256（镜像为 digest）',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `deleted` tinyint(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`),
  KEY `idx_app_name` (`app_name`),
  KEY `idx_pipeline_run_id` (`pipeline_run_id`),
  KEY `idx_pipeline_run_name` (`pipeline_run_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb3 COMMENT='制品信息表，记录流水线构建产出的制品信息';
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | 自增主键 |
| `app_name` | varchar(200) | 是 | 应用名称，与 `app_info.app_name` 对应 |
| `name` | varchar(255) | 是 | 制品名称。Raw 类型为二进制文件名（如 `go-web-demo`）；Image 类型为镜像 repo 路径（如 `go-web-demo/dev`） |
| `type` | varchar(20) | 是 | 制品类型枚举：`RAW` / `IMAGE` |
| `git_branch` | varchar(255) | 否 | 构建分支 |
| `commit_id` | varchar(64) | 否 | 构建 commit |
| `env` | varchar(30) | 否 | 环境标识 |
| `build_time` | datetime | 否 | 构建时间（由 Argo pod 回传） |
| `build_user` | varchar(255) | 否 | 构建人，后端通过 `pipeline_run_name` 反查 `pipeline_run.creator` 填充，pod 不传 |
| `pipeline_run_id` | bigint | 否 | 流水线运行 ID，对应 `pipeline_run.id`（后端通过 argo 回传的 name 反查得到） |
| `pipeline_run_name` | varchar(200) | 否 | 流水线运行名称，对应 `pipeline_run.name`（即 Argo Workflow name），用于跳转流水线执行详情 |
| `artifact_repository` | varchar(255) | 否 | Nexus3 仓库名 |
| `artifact_repository_path` | varchar(512) | 否 | 仓库内相对路径 |
| `artifact_url` | varchar(1024) | 否 | 制品完整地址，由 Argo 脚本拼接回传 |
| `size` | bigint | 否 | 制品大小（字节） |
| `sha256` | varchar(65) | 否 | sha256 值，镜像制品为 digest |

### 3.3 索引设计

| 索引名 | 字段 | 用途 |
|--------|------|------|
| `PRIMARY` | `id` | 主键 |
| `idx_app_name` | `app_name` | 制品列表页按应用筛选 |
| `idx_pipeline_run_id` | `pipeline_run_id` | 流水线详情页按运行查询制品 |
| `idx_pipeline_run_name` | `pipeline_run_name` | 按运行名称查询（回传反查、详情页跳转） |

```java
    @Override
    public Long upload(ArtifactUploadRequest request) {
        // 参数校验
        validateUploadRequest(request);

        Artifact entity = new Artifact();
        BeanUtils.copyProperties(request, entity);

        // 通过 pipelineRunName 反查 pipeline_run 记录，填充 pipelineRunId 和 buildUser
        if (StringUtils.hasText(request.getPipelineRunName())) {
            PipelineRun run = pipelineRunRepository.selectByName(request.getPipelineRunName());
            if (run != null) {
                entity.setPipelineRunId(run.getId());
                entity.setBuildUser(run.getCreator());
            }
        }

        artifactRepository.insert(entity);
        log.info("制品上传成功, appName={}, name={}, type={}, id={}",
                entity.getAppName(), entity.getName(), entity.getType(), entity.getId());
        return entity.getId();
    }

    @Override
    public ArtifactResponse getById(Long id) {
        Artifact entity = artifactRepository.selectById(id);
        if (entity == null) {
            throw new BusinessException(ArtifactConstants.MSG_ARTIFACT_NOT_EXIST);
        }
        return toResponse(entity);
    }

    @Override
    public PageResponse<ArtifactResponse> page(ArtifactQueryRequest query) {
        long pageNum = query.getPageNum() == null ? CommonConstants.DEFAULT_PAGE_NUM : query.getPageNum();
        long pageSize = query.getPageSize() == null ? CommonConstants.DEFAULT_PAGE_SIZE : query.getPageSize();
        // 默认按 id 倒序
        String sortField = SortUtil.resolveField(
                query.getSortField() != null ? query.getSortField() : "id", SORT_FIELD_MAP);
        String sortOrder = sortField != null
                ? SortUtil.resolveOrder(query.getSortOrder() != null ? query.getSortOrder() : "desc")
                : null;

        IPage<Artifact> pageResult = artifactRepository.pageQuery(
                pageNum, pageSize, query.getAppName(), query.getName(),
                query.getGitBranch(), query.getEnv(), query.getType(), sortField, sortOrder);

        List<ArtifactResponse> records = pageResult.getRecords().stream()
                .map(this::toResponse)
                .collect(Collectors.toList());

        return PageResponse.of(records, pageResult.getTotal(), pageResult.getCurrent(),
                pageResult.getSize(), pageResult.getPages());
    }

    @Override
    public List<ArtifactResponse> listByPipelineRunName(String pipelineRunName) {
        if (!StringUtils.hasText(pipelineRunName)) {
            return Collections.emptyList();
        }
        return artifactRepository.selectByPipelineRunName(pipelineRunName).stream()
                .map(this::toResponse)
                .collect(Collectors.toList());
    }

    private void validateUploadRequest(ArtifactUploadRequest request) {
        if (!StringUtils.hasText(request.getAppName())) {
            throw new BusinessException("应用名称不能为空");
        }
        if (!StringUtils.hasText(request.getName())) {
            throw new BusinessException(ArtifactConstants.MSG_ARTIFACT_NAME_REQUIRED);
        }
        if (!StringUtils.hasText(request.getType())) {
            throw new BusinessException(ArtifactConstants.MSG_ARTIFACT_TYPE_REQUIRED);
        }
        // 校验 type 枚举
        boolean validType = false;
        for (ArtifactTypeEnum e : ArtifactTypeEnum.values()) {
            if (e.getCode().equals(request.getType())) {
                validType = true;
                break;
            }
        }
        if (!validType) {
            throw new BusinessException(ArtifactConstants.MSG_ARTIFACT_TYPE_INVALID);
        }
    }

    private ArtifactResponse toResponse(Artifact entity) {
        if (entity == null) return null;
        ArtifactResponse response = new ArtifactResponse();
        BeanUtils.copyProperties(entity, response);
        return response;
    }
}
```

> **说明**：`PipelineRunRepository.selectByName()` 为已有方法（`pipeline_run.name` 即 Argo Workflow name）。如该方法不存在，需在 `PipelineRunRepository` 和 `PipelineRunMapper` 中补充。

### 6.2 新增：原始制品上传 Nexus3 模板

文件：`pipeline-manifests/basetasktemplate/nexus3/push-raw-nexus3.yaml`

**设计思路：**
- 语言无关的通用模板，任何语言构建产出的原始制品都可复用。
- 通过入参指定制品路径、目标仓库、仓库路径，适配不同语言上传到不同 repository。
- 上传成功后计算 sha256 和 size，拼接 artifact_url，回传后端。
- 回传逻辑内嵌在脚本末尾，保证上传成功才回传的原子性。

**入参设计：**

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `pipeline-run-name` | 是 | - | Argo Workflow name（回传用） |
| `app-name` | 是 | - | 应用名称 |
| `env` | 是 | - | 环境标识 |
| `git-branch` | 是 | - | git 分支 |
| `git-commit-id` | 是 | - | commit id |
| `build-artifact-path` | 是 | - | 制品在 PVC 上的绝对路径 |
| `nexus-raw-base-url` | 否 | `http://192.168.10.134:8081` | Nexus3 web 端口 |
| `nexus-raw-repo` | 是 | - | Nexus3 raw 仓库名（不同语言可不同） |
| `nexus-raw-repo-path` | 是 | - | 仓库内相对路径（如 `go-web-demo/20260724.master.a1b2c3d`） |
| `nexus-credential-secret` | 否 | `nexus-credentials` | 凭据 Secret 名 |

**出参设计：**

| 参数 | 说明 |
|------|------|
| `artifact-url` | 制品完整下载地址 |
| `artifact-sha256` | sha256 |
| `artifact-size` | 制品大小（字节） |

**核心脚本逻辑：**

```bash
set -eu

# ---------- 颜色 ----------
C_Y='\033[1;33m'; C_R='\033[1;31m'; C_OFF='\033[0m'
info()  { printf "${C_Y} [Info] %s${C_OFF}\n"  "$*"; }
error() { printf "${C_R} [Error] %s${C_OFF}\n" "$*"; }

readonly EXIT_USER_ERROR=100
readonly EXIT_EXTERNAL_ERROR=170

# ---------- 入参 ----------
artifact_path="{{inputs.parameters.build-artifact-path}}"
nexus_base_url="{{inputs.parameters.nexus-raw-base-url}}"
repo="{{inputs.parameters.nexus-raw-repo}}"
repo_path="{{inputs.parameters.nexus-raw-repo-path}}"

# ---------- 1. 校验制品文件 ----------
if [ ! -f "$artifact_path" ]; then
  error "制品文件不存在: $artifact_path"
  exit "$EXIT_USER_ERROR"
fi

filename=$(basename "$artifact_path")
size=$(stat -c %s "$artifact_path" 2>/dev/null || stat -f %z "$artifact_path")

# ---------- 2. 上传到 Nexus3 raw 仓库 ----------
target_url="${nexus_base_url}/repository/${repo}/${repo_path}/${filename}"
info "上传制品到 Nexus3: ${target_url}"

if ! curl -s --retry 3 --retry-max-time 60 --retry-all-errors \
    -u "${NEXUS_USERNAME}:${NEXUS_PASSWORD}" \
    --upload-file "$artifact_path" \
    "$target_url"; then
  error "制品上传失败: ${target_url}"
  exit "$EXIT_EXTERNAL_ERROR"
fi

info "制品上传成功"

# ---------- 3. 计算 sha256 ----------
sha256=$(sha256sum "$artifact_path" | awk '{print $1}')

# ---------- 4. 回传后端 ----------
info "回传制品信息到 pipeline-server..."

data=$(jq -n \
  --arg appName "{{inputs.parameters.app-name}}" \
  --arg name "$filename" \
  --arg type "RAW" \
  --arg gitBranch "{{inputs.parameters.git-branch}}" \
  --arg commitId "{{inputs.parameters.git-commit-id}}" \
  --arg env "{{inputs.parameters.env}}" \
  --arg buildTime "$(date -u +%Y-%m-%dT%H:%M:%S+08:00)" \
  --arg pipelineRunName "{{inputs.parameters.pipeline-run-name}}" \
  --arg repo "$repo" \
  --arg repoPath "${repo_path}/${filename}" \
  --arg url "$target_url" \
  --argjson size "$size" \
  --arg sha256 "$sha256" \
  '{
    appName: $appName,
    name: $name,
    type: $type,
    gitBranch: $gitBranch,
    commitId: $commitId,
    env: $env,
    buildTime: $buildTime,
    pipelineRunName: $pipelineRunName,
    artifactRepository: $repo,
    artifactRepositoryPath: $repoPath,
    artifactUrl: $url,
    size: $size,
    sha256: $sha256
  }')

res=$(curl -s --retry 3 --retry-max-time 60 --retry-all-errors \
  --request POST \
  --url "${PIPELINE_SERVER_URL}/artifact/upload" \
  --header 'Content-Type: application/json; charset=utf-8' \
  --data "$data")

echo "${res}"

code=$(echo "${res}" | jq -r '.code')
if [ "${code}" != "200" ]; then
  error "制品信息回传失败: ${res}"
  exit "$EXIT_EXTERNAL_ERROR"
fi

info "制品信息回传成功"

# ---------- 5. 出参 ----------
echo -n "$target_url" > /tmp/artifact-url
echo -n "$sha256" > /tmp/artifact-sha256
echo -n "$size" > /tmp/artifact-size
```

```bash
  --arg type "IMAGE" \
  --arg gitBranch "{{inputs.parameters.git-branch}}" \
  --arg commitId "{{inputs.parameters.git-commit-id}}" \
  --arg env "{{inputs.parameters.env}}" \
  --arg buildTime "$(date -u +%Y-%m-%dT%H:%M:%S+08:00)" \
  --arg pipelineRunName "{{inputs.parameters.pipeline-run-name}}" \
  --arg repo "{{inputs.parameters.nexus-docker-registry}}" \
  --arg repoPath "{{inputs.parameters.nexus-repo-name}}" \
  --arg url "$target_ref" \
  --argjson size "$image_size" \
  --arg sha256 "${digest:-unknown}" \
  '{
    appName: $appName,
    name: $name,
    type: $type,
    gitBranch: $gitBranch,
    commitId: $commitId,
    env: $env,
    buildTime: $buildTime,
    pipelineRunName: $pipelineRunName,
    artifactRepository: $repo,
    artifactRepositoryPath: $repoPath,
    artifactUrl: $url,
    size: $size,
    sha256: $sha256
  }')

res=$(curl -s --retry 3 --retry-max-time 60 --retry-all-errors \
  --request POST \
  --url "${PIPELINE_SERVER_URL}/artifact/upload" \
  --header 'Content-Type: application/json; charset=utf-8' \
  --data "$data")

echo "${res}"

code=$(echo "${res}" | jq -r '.code')
if [ "${code}" != "200" ]; then
  error "镜像制品信息回传失败: ${res}"
  exit "$EXIT_EXTERNAL_ERROR"
fi

info "镜像制品信息回传成功"
```

### 6.4 改造：go-cicd-pipeline 编排

在 `go-cicd-pipeline.yaml` 的 DAG 中，`go-build` 之后、`go-build-image` 之前，插入 `push-raw-nexus3` 节点。

**改造后的 DAG 依赖链：**

```
git-sync → go-build → push-raw-nexus3 ──────────────────┐
                │                                         │
                └──→ go-build-image → push-image-nexus3 ──┴──→ go-k8s-deploy-via-api
                    (打包镜像 tar)      (推送镜像+回传)        (部署，需等原始制品和镜像都完成)
```

## 7. 回传数据流

### 7.1 原始制品回传

```
go-build 产出二进制 (PVC)
    │
    ▼
push-raw-nexus3
    ├── curl --upload-file 上传到 Nexus3 raw 仓库
    ├── sha256sum 计算 sha256
    ├── stat 获取 size
    ├── 拼接 artifact_url
    └── curl POST /artifact/upload
            │
            │  { appName, name, type: "RAW", ..., pipelineRunName, ... }
            │
            ▼
        pipeline-server
            ├── 校验参数
            ├── 查 pipeline_run (by name) → id + creator
            │   ├── pipelineRunId = run.id
            │   └── buildUser = run.creator
            ├── INSERT artifact
            └── 返回制品 ID
```

### 7.2 镜像制品回传

```
go-build-image 产出镜像 tar (PVC)
    │
    ▼
push-image-nexus3
    ├── skopeo copy 推送到 Nexus3 docker-hosted
    ├── skopeo inspect 获取 digest (sha256) 和 size
    ├── target_ref 作为 artifact_url
    └── curl POST /artifact/upload
            │
            │  { appName, name, type: "IMAGE", ..., pipelineRunName, ... }
            │
            ▼
        pipeline-server
            ├── 校验参数
            ├── 查 pipeline_run.creator → buildUser
            ├── INSERT artifact
            └── 返回制品 ID
```

## 9. 设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 回传是否做成独立任务模板 | **否，内嵌在上传/推送脚本中** | 保证上传成功才回传的原子性，避免数据不一致 |
| build_user 如何获取 | **后端通过 pipelineRunName 反查 pipeline_run.creator** | pod 不需要感知用户信息，解耦 |
| pipeline_run_id 如何获取 | **后端通过 pipelineRunName 反查 pipeline_run.id** | argo 只传 name，后端负责反查 id |
| artifact_url 由谁拼接 | **Argo 脚本拼接回传** | 脚本最清楚 Nexus3 完整地址（web port vs registry port），后端不感知 Nexus3 地址 |
| 回传接口鉴权 | **免鉴权（@RequireLogin(false)）** | 内部接口，Argo pod 在集群内访问，学习项目无需复杂鉴权 |
| 回传接口地址管理 | **ConfigMap** | 换环境只改 ConfigMap，不改模板 |
| 原始制品上传方式 | **Nexus3 REST API（curl --upload-file）** | Nexus3 3.x raw 仓库原生支持，简单可靠 |
| 不同语言上传不同 repository | **通过模板入参 nexus-raw-repo 指定** | 模板统一，参数差异化 |
| 流水线详情页制品展示 | **基本信息区 el-popover hover 卡片** | 全局视角，一次看到所有制品，交互轻量 |
| 制品列表默认排序 | **按 id 倒序** | 最新构建的制品排最前 |
